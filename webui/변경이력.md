## 2026-07-31 — 최초 구성 (커밋 `dbff80d`)

**목표**: TradingAgents 웹 UI를 AWS에 구축. 서울 리전 사용(미지원 서비스만 us-east-1),
Bedrock 모델은 us-east-1 연결, 시스템은 외부 비노출 + CloudFront URL로만 접근.

구축 내용:

- **프론트엔드** (`webui/frontend/`): 한국어 다크 테마 SPA — 분석 시작 폼, 실행 목록(10초 폴링, 상태·결정 뱃지, 경과 시간), 마크다운 보고서 뷰어(marked.js 로컬 번들). 해시 라우팅.
- **Lambda API** (`webui/backend/api_handler.py`): 실행 생성(ECS RunTask 트리거)/목록/상세/보고서 조회. boto3만 사용해 zip 한 장으로 배포. 동시 실행 3건 제한.
- **Fargate 워커** (`webui/worker/`): 분석 1건당 태스크 1개. DynamoDB에서 파라미터를 읽어 TradingAgents 그래프 실행 → 한국어 보고서를 S3 업로드 → 상태 기록. 30초 하트비트.
- **인프라** (`webui/infra/template.yaml`, 서울 리전 CloudFormation 단일 스택 `tradingagents-webui`): S3×2(사이트/데이터), DynamoDB, ECR, ECS 클러스터+태스크 정의, Lambda+Function URL, CloudFront(+OAC×2), CodeBuild, IAM 역할 일체.
- **접근 제어(당시)**: CloudFront 함수로 Basic 인증. S3/Lambda는 OAC로 CloudFront 전용, 워커는 인바운드 없음.
- **리전 구성**: 시스템 전체 서울. Bedrock만 us-east-1 (워커 컨테이너 `AWS_REGION=us-east-1`, 시스템 리소스는 `HOME_REGION`으로 분리 접근). 모델: Sonnet 4.5(deep)/Haiku 4.5(quick).
- 로컬에 Docker가 없어 **CodeBuild로 이미지 빌드** (소스 zip을 S3에 올려 빌드).

### 구축 중 해결한 문제

1. **CloudFront→Lambda 403 (가장 큰 삽질)**: OAC가 서명한 요청을 Lambda가 계속 거부.
   원인은 권한 부족 — OAC용 Lambda URL은 `lambda:InvokeFunctionUrl`뿐 아니라
   **`lambda:InvokeFunction` 권한도 함께** 필요 (공식 문서에만 있는 요구사항).
   진단 과정에서 403→index.html 오류 페이지 매핑이 API 오류를 가려 제거함.
2. **Basic 인증 ↔ OAC 충돌**: 뷰어의 `Authorization` 헤더가 오리진까지 전달되면
   OAC SigV4 서명과 충돌 → CloudFront 함수에서 검증 후 헤더 삭제로 해결.
3. **OAC POST 본문 서명**: CloudFront OAC는 POST 본문을 서명하지 않으므로
   클라이언트가 `x-amz-content-sha256`(본문 SHA-256) 헤더를 직접 전송하도록 프론트 수정.
4. **오리진 요청 정책**: 커스텀 최소 정책을 시도했으나 `x-amz-content-sha256`은
   정책 허용 목록에 넣을 수 없는 예약 헤더 → AWS 권장 관리형 정책
   `AllViewerExceptHostHeader`로 확정.

## 2026-07-31 — 종단 검증 및 안정화 (커밋 `8ff5461`)

첫 실전 분석(SPY, 얕게)이 8분 진행 후 실패:
`ReadTimeoutError ... bedrock-runtime.us-east-1...`

- **원인**: botocore 기본 읽기 타임아웃 60초. 한국어 보고서처럼 긴 LLM 생성이 60초를 초과.
- **수정**: `tradingagents/llm_clients/bedrock_client.py`에서 읽기 타임아웃을 300초로
  연장 (`TRADINGAGENTS_BEDROCK_READ_TIMEOUT`으로 조정 가능). 이 수정은 웹 UI뿐
  아니라 CLI의 Bedrock 사용에도 적용됨.
- **보고서 경로 매핑 수정**: 실제 저장 경로가 `1_analysts/market.md`처럼 번호
  접두사가 붙는 것을 확인하고 프론트 한국어 레이블 매핑을 실경로로 교정.
- **재검증 성공**: SPY 분석 약 9분 완료, 최종 결정 "Underweight", 한국어 보고서
  13개 생성·열람 확인.
- 그 외: Rich 콘솔 줄바꿈/ANSI 코드에 취약하던 테스트 1건 보강.

## 2026-08-01 — 인증을 Cognito User Pool로 교체 (커밋 `13c65d0`)

**요청**: 계정을 기존에 구성된 Cognito User Pool로 다시 연결.

- 기존 **`household-ledger-users` 풀**(`ap-northeast-2_beRiSnPMY`, 가계부·rtms 공유)에
  앱 클라이언트 **`tradingagents-web`**(`11ikj0bqsifr90tf4b37h4t14p`) 추가 —
  기존 앱들과 동일한 패턴(시크릿 없음, USER_PASSWORD_AUTH, 액세스 1시간/리프레시 30일).
- **프론트엔드**: 로그인 화면 추가(이메일/비밀번호, SDK 없이 cognito-idp REST 직접 호출),
  토큰 localStorage 저장, 만료 1분 전 선제 갱신 + 401 시 1회 갱신 후 재시도,
  로그아웃 버튼, 헤더에 로그인 이메일 표시. 설정은 `config.js`로 분리.
- **Lambda API**: 모든 요청에서 `x-access-token` 헤더의 액세스 토큰을 Cognito
  `GetUser`로 검증. client_id(이 앱 클라이언트 한정)·token_use 클레임 확인,
  5분 검증 캐시. 미인증 401.
- **인프라**: CloudFront Basic 인증 함수·토큰 파라미터 제거,
  `CognitoClientId` 파라미터 추가.
- 토큰은 OAC 서명과 충돌하는 `Authorization` 대신 **`x-access-token`** 헤더로 전달.
- 검증: 임시 사용자로 로그인→API 호출 확인 후 삭제(풀에는 가족 계정 2개만 유지).

## 2026-08-01 — 브라우저 캐시 문제 수정 (이 문서와 함께 커밋)

**증상**: 인증 교체 배포 후 새로고침해도 로그인 화면이 나오지 않음.

- **원인**: S3 정적 파일에 `Cache-Control` 헤더가 없어, CloudFront는 새 파일을
  서빙하는데 **브라우저가 자체 휴리스틱 캐시로 구버전을 계속 사용**.
- **수정**: 모든 정적 파일에 `Cache-Control: no-cache` 설정(기존 객체 일괄 적용 +
  deploy.sh의 sync에 옵션 추가). 브라우저가 매번 ETag로 재검증하므로 이후 배포는
  즉시 반영됨 (변경 없으면 304라 부담 없음).
- 기존에 열려 있던 탭은 **강력 새로고침(Cmd+Shift+R / Ctrl+F5) 1회** 필요.
  이후로는 일반 새로고침으로 항상 최신 버전.
- 문서 추가: `webui/아키텍처.md`(구조·데이터·사용법), `webui/변경이력.md`(이 문서).

  이후 접속 주소는 **https://stock.happymstn.com** (기존 CloudFront URL도 유효).
