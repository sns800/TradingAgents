## 1. 한눈에 보기

기존 웹 UI는 종목 분석만 할 수 있었고, 거시 근거는 뉴스 분석가가 FRED(미국)만 수치로 쓰던 상태였습니다.
그래서 **G20 20개국(19개국 + 유로존)의 정치·통화·경제구조·재정·시장 데이터를 공식 통계 API에서 매일 모아
DynamoDB에 누적하고, 브라우저에서 히트맵·시계열·국가 프로필로 볼 수 있는 탭 하나**를 추가했습니다.
숫자는 공식 통계만 쓰고, LLM은 "숫자로 안 나오는 것"(중앙은행 기조 판정·여론조사 표 추출·에너지 정책 요약)에만 씁니다.
관측치 1건 단위로 **출처·시리즈 ID·수집 시각·vintage·개정 이력**을 보존하므로, 사람이 보는 대시보드이면서
동시에 `vintage ≤ 분석일` 조건으로 과거 시점 스냅샷을 만들 수 있는(= 백테스트 룩어헤드 차단) 데이터 자산이 됩니다.
인프라는 새로 만들지 않고 기존 스택에 **DynamoDB 테이블 1개 + EventBridge 규칙 1개**만 더했습니다.

- **리전**: 시스템 전체 서울(`ap-northeast-2`). **Bedrock만 us-east-1**(기존 분석 워커와 동일 규칙).
- **추가된 인프라 리소스는 4종뿐**입니다 — `MacroTable`(DynamoDB, PITR + `DeletionPolicy: Retain`),
  `MacroScheduleRule`(EventBridge, `State`는 파라미터 `MacroScheduleEnabled`로 on/off),
  IAM 권한 2곳(워커·API), 워커/Lambda 환경변수. EventBridge 실행 역할은 카탈로그 배치의 `CatalogScheduleRole`을

- 스택 파라미터는 총 15개이고 그중 매크로용이 5개입니다(`FredApiKey`·`EmberApiKey` NoEcho, `MacroLlmModel`,
  `MacroLlmDailyTokenBudget`, `MacroScheduleEnabled` — `aws cloudformation validate-template` 실측).
